# Dashboards: описание проекта

Статус: **черновик для ревью**. Решения помечены как «принято» (подтверждено в обсуждении) или «предложение» (моё, ждёт подтверждения). Код по этому документу ещё не писался.

## 1. Цель

BI-сервис: пользователь регистрируется, подключает публичную Google Таблицу как датасет, собирает из датасетов дашборд из графиков на drag-and-resize сетке и встраивает дашборд через `<iframe>` на другие сайты.

Контекст: пет-проект для портфолио и собеседований (Яндекс). Поэтому ценность не только в функциональности, но и в том, что можно показать: безопасность (auth, embed, SSRF), производительность грида, тесты, продуманная схема данных.

### Что не входит (YAGNI)
- Приватные таблицы и Google OAuth для Sheets (принято: только публичные).
- Другие источники (Postgres, CSV-загрузка): в схеме закладываем `sourceType`, но реализуем только Google Sheets.
- Командная работа, роли, шаринг между пользователями.
- SQL-редактор, вычисляемые поля, фильтры дашборда (возможное расширение).
- Realtime-совместное редактирование.

## 2. Текущее состояние кода

- Next.js 16.2.4 (App Router), React 19, TypeScript strict, Tailwind 4.
- Chart.js + react-chartjs-2: компонент `src/entities/chart/ui/Chart.tsx`.
- Свой грид на dnd-kit: `src/shared/ui/DndGrid/`, чистая логика в `core/` (`core.ts`, `collisions.ts`, `compactor.ts`, `calc.ts`, `element.ts`, `type.ts`).
- Prisma 7 + PostgreSQL: `server/db/prisma/schema.prisma`, одна init-миграция. В коде не используется.
- Единственная страница `src/pages/main/example.tsx`: 5 графиков на случайных данных faker, без сохранения.
- Структура `src/` в духе Feature-Sliced Design: `app`, `pages`, `widgets`, `features`, `entities`, `shared`, часть слоёв пока пустая (`.gitkeep`).
- Нет тестов, авторизации, валидации, реального API (`/api/hello` — заглушки).

Известные проблемы грида (войдут в подпроект 5):
- `isLocked` блокирует перетаскивание, но не resize.
- Resize за левый нижний угол (`lb`) считает высоту иначе, чем за правый (`rb`), вероятно неверно.
- Число колонок измеряется один раз при монтировании, окно не отслеживается.
- Новый элемент может лечь поверх другого (запасной вариант — позиция 0,0).
- На каждый drag-move выполняется `structuredClone`, пересортировка и пересчёт всей раскладки; нет memo и троттлинга.
- В `DndGrid.tsx` импортируются `@dnd-kit/dom` и `@dnd-kit/abstract`, которых нет в `package.json`.

> Важно (из AGENTS.md): эта версия Next.js отличается от привычной. Перед написанием кода читать соответствующие руководства в `node_modules/next/dist/docs/` (в частности про маршруты, заголовки, кэширование и перехват запросов: возможны переименования API).

## 3. Решения

| # | Решение | Статус |
|---|---------|--------|
| 1 | Источник данных: только публичные Google Таблицы по ссылке | принято |
| 2 | Вход в сервис: Auth.js (NextAuth) с credentials | принято |
| 3 | Embed: токен + список разрешённых доменов | принято |
| 4 | Датасет: снимок в БД, обновление по TTL и вручную | принято |
| 5 | Формат снимка: JSONB (`columns` + `rows`) в одной записи | предложение |
| 6 | Обновление: ленивое, stale-while-revalidate, без cron | предложение |
| 7 | Валидация на всех границах через zod | предложение |
| 8 | Тесты: vitest (логика), Playwright (1–2 сквозных сценария) | предложение |

Следствие решения 2: credentials-провайдер Auth.js работает только с JWT-сессиями, не с сессиями в БД. Мы используем JWT в httpOnly-cookie; отзыв сессий до истечения срока придётся делать через `tokenVersion` в `User` (если понадобится).

## 4. Декомпозиция

Пять подпроектов, у каждого свой spec → план → реализация. Порядок важен: 2–4 зависят от 1.

1. **Фундамент**: auth, схема, CRUD дашбордов, сохранение раскладки.
2. **Датасеты и Google Sheets**: импорт, типы столбцов, снимок, обновление.
3. **Конструктор графиков**: привязка датасета к блоку, настройка графика.
4. **Embed**: публичный доступ по токену, домены, iframe.
5. **Ядро грида**: тесты, баги, перф. Почти независим, можно делать параллельно.

Дальнейшие разделы описывают целевую систему целиком; границы подпроектов указаны в пометках.

## 5. Модель данных (предложение)

Существующую схему в основном переписываем: убираем неявные many-to-many (`Block`↔`ContentBlock`, `ContentBlock`↔`Chart`), `DataContent` (построчное хранение, неудобно для графиков) и `Connection` с открытым `urlConnect`.

```prisma
model User {
  id           String      @id @default(cuid())
  email        String      @unique
  passwordHash String
  name         String?
  createdAt    DateTime    @default(now())
  dashboards   Dashboard[]
  datasets     Dataset[]
}

model Dashboard {
  id         String      @id @default(cuid())
  ownerId    String
  owner      User        @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  title      String
  blocks     Block[]
  embedLink  EmbedLink?
  createdAt  DateTime    @default(now())
  updatedAt  DateTime    @updatedAt
}

model Block {
  id          String    @id @default(cuid())
  dashboardId String
  dashboard   Dashboard @relation(fields: [dashboardId], references: [id], onDelete: Cascade)
  x           Int
  y           Int
  w           Int
  h           Int
  kind        BlockKind          // CHART | TEXT
  datasetId   String?
  dataset     Dataset?  @relation(fields: [datasetId], references: [id], onDelete: SetNull)
  config      Json               // zod-схема зависит от kind
}

model Dataset {
  id           String        @id @default(cuid())
  ownerId      String
  owner        User          @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  name         String
  sourceType   SourceType    // GOOGLE_SHEET
  spreadsheetId String
  gid          String
  ttlSeconds   Int           @default(3600)
  columns      Json?         // [{ name, type: "number" | "string" | "date" }]
  rows         Json?         // массив массивов по порядку columns
  rowCount     Int           @default(0)
  fetchedAt    DateTime?
  status       DatasetStatus @default(PENDING) // PENDING | READY | ERROR
  lastError    String?
  failCount    Int           @default(0)
  blocks       Block[]
  @@unique([ownerId, spreadsheetId, gid])
}

model EmbedLink {
  id             String    @id @default(cuid())
  dashboardId    String    @unique
  dashboard      Dashboard @relation(fields: [dashboardId], references: [id], onDelete: Cascade)
  tokenHash      String    @unique   // SHA-256 от токена; сам токен показывается один раз
  allowedOrigins String[]            // нормализованные origin: https://example.com
  revokedAt      DateTime?
  createdAt      DateTime  @default(now())
}
```

Замечания:
- Координаты блока целочисленные (в клетках грида), а не `Float`, как сейчас.
- `config` — JSONB, форма проверяется zod по `kind`. Для графика: тип, столбец подписей, столбец значений, агрегация, цвет, легенда.
- `rows` в JSONB выбран ради быстрого чтения одним запросом. Лимит снимка: 50 000 строк / 5 МБ (значения настраиваются); при превышении импорт завершается понятной ошибкой.
- Токен embed хранится только хэшем. Если потерян, пересоздаётся (старый отзывается).
- Выбор `onDelete` отражает намерение: удаление датасета не удаляет блоки, а оставляет их «пустыми» с понятным состоянием.

## 6. Подсистемы

### 6.1 Авторизация (подпроект 1)
- Регистрация и вход по email + пароль; пароль хэшируется (argon2id или bcrypt с достаточным cost).
- Auth.js, JWT-сессия в httpOnly + Secure + SameSite=Lax cookie.
- Защита маршрутов: страницы дашбордов и API требуют сессию; проверка владения (`ownerId`) на каждом доступе к дашборду и датасету, а не только вход.
- Rate limiting на вход и регистрацию (по IP и по email).
- Единый ответ при неверном email или пароле, чтобы не раскрывать существование аккаунта.
- Валидация входных данных через zod (длина, формат email, минимальная сложность пароля).

### 6.2 Дашборды и раскладка (подпроект 1)
- CRUD дашбордов: список, создание, переименование, удаление.
- Редактор: существующий `DndGrid`, раскладка сохраняется в `Block` (x, y, w, h).
- Сохранение: debounce после drag/resize или явная кнопка; оптимистичное обновление, откат при ошибке.
- Блокировка редактирования (`isLocked`) вынесена в переключатель интерфейса.
- Версионирование раскладки не нужно; защита от гонки двух вкладок — `updatedAt` как оптимистичная блокировка (предложение).

### 6.3 Датасеты и Google Sheets (подпроект 2)
Пользователь вставляет ссылку вида `https://docs.google.com/spreadsheets/d/<id>/edit#gid=<gid>`.

Импорт:
1. Из ссылки **регулярным выражением** извлекаются `spreadsheetId` и `gid`. Сервер **не обращается по URL, введённому пользователем**: он строит собственный адрес `https://docs.google.com/spreadsheets/d/<id>/export?format=csv&gid=<gid>`. Это закрывает SSRF.
2. Запрос с таймаутом, лимитом размера ответа (потоковое чтение с прерыванием) и ограничением редиректов (только на домены Google).
3. Если таблица не публична, Google возвращает страницу входа: распознаём и возвращаем понятную ошибку «таблица не открыта по ссылке».
4. Парсинг CSV (корректно: кавычки, переносы строк внутри ячеек, BOM).
5. Определение типов столбцов по выборке: number (с учётом десятичной запятой и пробелов-разделителей), date (ISO и частые форматы), иначе string. Пустые значения допускаются.
6. Сохранение снимка: `columns`, `rows`, `rowCount`, `fetchedAt`, `status = READY`.

Обновление (ленивое, stale-while-revalidate):
- При чтении датасета проверяется `fetchedAt + ttlSeconds`. Если снимок устарел, отдаются имеющиеся данные, а в фоне запускается обновление.
- Один одновременный refresh на датасет (блокировка через `pg_advisory_lock` или условный `UPDATE ... WHERE status != 'REFRESHING'`).
- При ошибке сохраняется предыдущий снимок, увеличивается `failCount`, пишется `lastError`; повторные попытки с экспоненциальной задержкой. Данные не стираются.
- Кнопка «Обновить сейчас» в интерфейсе (с ограничением частоты).
- В Next 16 фоновую работу внутри запроса нужно делать способом, поддерживаемым этой версией (`after`-подобный API): проверить по `node_modules/next/dist/docs/`.

UI: список датасетов, форма добавления, превью первых строк, типы столбцов с возможностью ручной правки, статус и время последнего обновления.

### 6.4 Конструктор графиков (подпроект 3)
- Добавление блока: выбор датасета и типа графика (bar, line, pie, donut).
- Настройки: столбец подписей, столбец значений, агрегация (sum, avg, count, min, max) с группировкой по подписи, сортировка, лимит категорий («топ N + прочее»), цвета, легенда, заголовок.
- Агрегация выполняется на сервере или в чистой функции над `rows` (предложение: чистая функция, одинаково работает для редактора и embed, легко тестируется).
- Блок `TEXT` — простой текстовый блок (заголовок/описание).
- Корректные состояния: нет данных, датасет в ошибке, столбец удалён или сменил тип.
- Существующий `Chart.tsx` дорабатывается: параметры `showLegend` и `title` сейчас игнорируются; опечатка `lable`.

### 6.5 Embed (подпроект 4)
Публичный доступ включается владельцем на странице дашборда.

- Генерируется криптостойкий токен (не менее 128 бит), показывается один раз; в БД хранится SHA-256.
- Владелец задаёт список разрешённых доменов (origin: схема + хост + порт; подстановочные маски — отдельное решение).
- Маршрут `/embed/[token]`: read-only отображение дашборда без редактора и без данных пользователя.
- Заголовки ответа маршрута embed: `Content-Security-Policy: frame-ancestors <allowedOrigins>`. Для пустого списка — `'none'`. Остальные маршруты приложения отдают `frame-ancestors 'none'` / `X-Frame-Options: DENY` (защита от clickjacking).
- Данные для embed читаются отдельным публичным эндпоинтом/серверным кодом, который принимает только токен, проверяет `revokedAt`, и отдаёт **только** данные блоков этого дашборда. Никаких сквозных идентификаторов, по которым можно перебрать чужие датасеты.
- Куки сессии не используются (в iframe на стороннем домене они всё равно блокируются); embed не зависит от авторизации зрителя.
- Токен в URL может попасть в логи и `Referer`: ставим `Referrer-Policy: no-referrer`, не логируем путь целиком.
- Rate limiting по токену и IP; кэширование ответа (короткий TTL), чтобы всплеск трафика на сайте-хосте не превращался в нагрузку на БД и на Google.
- Отзыв: «отозвать токен» (мгновенно), «перевыпустить».
- UI: переключатель публичного доступа, список доменов, готовый сниппет `<iframe src="..." width height loading="lazy">`, предпросмотр.
- Адаптивность: embed подстраивается под размер iframe (брейкпоинты грида).

Что `frame-ancestors` даёт и не даёт: браузер не покажет страницу во фрейме на чужом домене, но токен остаётся «bearer»-секретом: кто его знает, увидит данные при открытии напрямую. Это принятая модель («публичная ссылка с отзывом»).

### 6.6 Ядро грида (подпроект 5)
- Тесты логики (`core/`): перемещение, resize, коллизии, компактор. Property-based (fast-check): после любой операции нет пересечений; компактор идемпотентен; результат не зависит от порядка входных элементов.
- Исправление багов из раздела 2.
- Производительность: убрать `structuredClone` на каждый drag-move, memo для `ItemGrid` и `Chart`, rAF-троттлинг, бенчмарк на 200–500 блоках, фиксация результатов «до/после».
- Возможное алгоритмическое улучшение: пространственный индекс вместо O(n²) обхода коллизий, сравнение бенчмарком.
- ResizeObserver для числа колонок.
- Доп. ручки resize, клавиатурное управление, a11y (по остаточному принципу).

## 7. Маршруты и API (предложение)

Страницы:
- `/login`, `/register`
- `/dashboards` — список
- `/dashboards/[id]` — редактор
- `/datasets` — список, `/datasets/new`, `/datasets/[id]`
- `/embed/[token]` — публичный просмотр

Mutations через Server Actions или Route Handlers (выбрать при реализации по документации Next 16); все с zod-валидацией и проверкой владения. Публичная поверхность — только `/embed/[token]` и связанные ему данные.

## 8. Безопасность (сводка)

| Риск | Мера |
|------|------|
| Подбор пароля | rate limiting, argon2id, единый ответ ошибки |
| Кража сессии | httpOnly + Secure + SameSite cookie |
| Доступ к чужим данным (IDOR) | проверка `ownerId` на каждый запрос, тесты на это |
| SSRF через ссылку на таблицу | сервер строит URL сам, разбирая только `id` и `gid` |
| DoS большим файлом | таймаут, лимит размера и строк, потоковое чтение |
| Clickjacking приложения | `frame-ancestors 'none'` везде, кроме embed |
| Встраивание на чужие сайты | `frame-ancestors` из списка владельца, токен с отзывом |
| Утечка токена embed | хэш в БД, `Referrer-Policy`, отзыв/перевыпуск |
| XSS через данные таблицы | данные только как значения для Chart.js и текстовые узлы, никакого `dangerouslySetInnerHTML` |
| Шторм запросов на Google | один refresh на датасет, backoff, кэш |
| Секреты | только в `.env`, не в репозитории |

## 9. Тестирование

- **vitest (unit):** парсинг CSV, определение типов, агрегации, нормализация origin, логика TTL/refresh, логика грида, zod-схемы.
- **Интеграционные:** Route Handlers/Actions с тестовой БД (проверка владения, лимиты, отзыв токена, заголовки embed).
- **Playwright (e2e):** регистрация → добавление датасета → построение графика → включение embed → открытие в iframe и проверка. Для Google — локальный mock-сервер с CSV, реальную сеть в тестах не трогаем.
- **Перф:** бенчмарк грида (подпроект 5).
- CI: lint + typecheck + unit.

## 11. Открытые вопросы
1. Хостинг (Vercel или VPS/Docker)? Влияет на фоновое обновление и rate limiting (нужен общий стор, если несколько инстансов).
2. Маски доменов (`*.example.com`) в списке разрешённых нужны или достаточно точных origin?
3. Лимиты снимка (50k строк / 5 МБ) подходят?
4. Один embed-токен на дашборд или несколько (по сайтам)? Сейчас в схеме один.
5. Нужны ли пользователю тёмная тема и адаптация под мобильные экраны в редакторе, или только в embed?
6. Язык интерфейса: русский, английский, оба?

## 12. Порядок работ и критерии готовности

1. **Фундамент:** пользователь может зарегистрироваться, войти, создать дашборд, двигать блоки, и раскладка сохраняется после перезагрузки. Чужие дашборды недоступны (тест).
2. **Датасеты:** по публичной ссылке создаётся датасет с корректными типами; недоступная таблица даёт понятную ошибку; refresh не стирает старые данные при сбое.
3. **Графики:** из датасета строится график четырёх типов с агрегацией; состояния ошибок отображаются.
4. **Embed:** дашборд открывается в iframe на разрешённом домене и блокируется на других; отзыв токена работает мгновенно.
5. **Грид:** тесты зелёные, баги закрыты, бенчмарк показывает улучшение.
